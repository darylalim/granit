# granit evaluation (PLAN.md §4.9)

Two eval sets in one format: **public** (here, synthetic, committed) and **private** (your documents, in `data/eval/`, never
committed). `1.0.0` is released only when both pass.

## Running

```bash
uv run granit eval run --set public                 # ~15 min: Phase A ingest + extract → B answers → C Guardian → metrics
uv run granit eval run --set public --no-judge      # skip Guardian
uv run granit eval run --set public --fresh         # re-ingest (after a model, Docling or chunking change)
uv run granit eval compare eval/results/A.json eval/results/B.json   # flags regressions of 2 points or more
```

Run it before merging any change to models, prompts, chunking or retrieval, and compare with the last result. Results hold
metrics, config and model revisions only, never document content: public ones go to `eval/results/` (commit them), private
ones to `data/eval/results/`. The set's library (ingested files, answers in `qa_turns`, Guardian verdicts) is kept in
`data/eval/libraries/<set>/` for debugging: `retrieval_trace` shows which stage lost the right chunk.

## The public set

Generated by `uv run python scripts/make_eval_fixtures.py` (needs Google Chrome and macOS `say`). Regenerate, don't
hand-edit: every expected value, page and time range comes from the data in that script.

| | |
|---|---|
| `files/invoices`, `files/forms` | 6 invoices (one a skewed scan) and 4 forms → `extraction/*.json` (schema + expected fields) |
| `files/reports` | 3 multi-page reports |
| `files/tables` | 8 hard tables (merged headers, borderless, skewed scan, split across pages, dense numbers, line breaks, 2 controls) → `tables/*.json` (every cell), for Docling vs Vision |
| `files/meetings` | 3 meetings in 4 `say` voices → `summaries/*.yaml` (action items), `transcripts/*.txt` (for WER) |
| `questions.yaml` | 31 questions: document, meeting, cross-source, unanswerable; `gold_refs` point at the page or time range |

## Your private set

```bash
uv run granit eval init --set private               # data/eval/: folders + a questions.yaml template
# put your documents and recordings in data/eval/files/, write ~30 questions with expected facts
uv run granit eval run --set private --no-judge     # ingests the files into the set's library
uv run granit eval label --set private              # ~2 min per question: tick the relevant chunks → gold_refs
uv run granit eval run --set private
```

Optional references, same format as the public set: `extraction/<name>.json`, `summaries/<name>.yaml`,
`transcripts/<name>.txt` (first line `file: files/…`), `tables/<name>.json`.

## Trusting the judge

Guardian is a Granite model judging a Granite model. Its metrics are **informational** until you've checked it:

```bash
uv run granit eval agreement --set public           # 50 verdicts by hand, y / n → judge_agreement.json
```

At ≥ 85 % agreement (Cohen's κ is reported too) Guardian's groundedness counts toward the pass criteria. Repeat after any
Guardian or prompt change.
